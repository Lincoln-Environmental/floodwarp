data downloads; nothing was overwritten or rerun merely to change scheduling.
The full conditioned DEM, FV1/LI/reference maxima, signed envelope differences,

These generated files are Git-ignored release data.

## 3. Sparse-default verification and performance

Native FV1 and factory/model calls selecting `solver_method='fv1'` default to
`execution_mode='sparse'`, `tile_size=8`, `dense_fraction=0.65`. The uniform grid,
dense FP64 state, HLL/contact formulation, sources/soil, complete source/boundary
CFL, donor budgets, boundaries, accepted transport, maxima and ledgers are
preserved. No shallow positive water is deleted. High work occupancy uses dense
indexing; explicit dense execution also avoids scheduling overhead.

| Retained complete 72-hour run | Hydraulic runtime [s] |
|---|---:|
| Dense FloodWarp FV1 | 1906.106 |
| Released exact-sparse FV1 | 1641.957 |
| External LISFLOOD-FP FV1 | 1403.559 |

The 13.9% FloodWarp runtime reduction is one candidate event against the retained
same-device dense benchmark, not interleaved full-event repetitions. All
1,570,053 accepted steps and all 72 recorded hourly numerical-field comparisons
agree. Widespread-runoff windows can be slower. The matched event uses explicit
discharge-extrapolated stages; native public defaults use velocity extrapolation.
This benchmark does not qualify every boundary closure or flood scenario.

Release checks passed: **965 CPU tests**, **1609 full CPU/CUDA tests** and
**75 focused tests against the installed wheel**. The wheel/source contents,
AGPL metadata, disclaimer and absence of static modules were inspected.
Release-tag and current-main GitHub CPU workflows passed. New development
numerical changes subsequently passed **1638 tests, 25 skipped**; existing
warnings were retained without tolerance relaxation.

## 4. Dense override, graphs and restart

`execution_mode='dense'` works in native FullSWESolver and both factories.
Controls cover wet/dry conditions, masked and prescribed-stage boundaries,
source activation/infiltration, 1e-10 m water, complete face histories, maxima,
ledgers, CUDA conditional graphs, partial tile release/reactivation and disk
restart in both sparse-to-dense and dense-to-sparse directions. Scheduling
caches reconstruct after restore and remain outside numerical restart identity.

The standalone Orton Bradley replay now reaches the exact requested final time
for shorter-than-interval and non-divisible durations, always saving final
state/checkpoint/ledger. It starts fresh, refuses a nonempty output directory
and **does not resume automatically**. Explicit restoration into an identically
configured model is required.

## 7. Development results and next gates

Dev uses **0.2.0.dev0** in both package code and installed metadata. Released
sparse uniform FV1 remains the normal execution path; dense is selectable.

The separate [performance investigation](../validation/sparse_perf_review/REPORT.md)
retains released-tile-only clearing and fused post-source activity detection.
The source and activity bodies are AST-identical to their originals; other
hydraulic functions are unchanged. Six interleaved saved-state phases, warm-up
and three repetitions give about **7–8% less wet-phase hydraulic time** than
released sparse execution, with zero compared field/time/step differences.
The short dry case is slightly slower. Earlier forced dense indexing was worse
and is rejected; independent gains are not multiplied. Candidate persistent and
separate live peak allocation are both 246,506,124 B, versus 246,386,556 B for
released sparse, excluding CUDA context/code/reserved memory. This is an
execution optimisation with extra scheduling memory, not sparse storage.

No new complete-event runtime is claimed for this candidate. Full-event
requalification is required before a later stable release. Measured remaining
costs are full-domain CFL/sources, first-step cache invalidation and
high-occupancy scheduling/indirection.

The separate [static investigation](../validation/static_reconstruction_review/REPORT.md)
preserves the failed 64×64 evidence and adds genuinely coarsenable 512×512
controls. Broad lake/front/ponding cases give **1.12–1.44× dense/static speedup**;
the protected active narrow channel remains slightly slower. Fine sources,
restriction/projection and scratch persist, and allocation does not decrease.
Smooth curved-lake equilibrium and a bounded moving-surface commutator are
recorded without changing the fine DEM or solver safeguards.

Actual Orton Bradley thin-runoff states often cannot be represented by one
constant coarse free surface. At hour 25, 87 of 139,576 fully wet parents pass
a positive 0.001 m reconstruction screen; none also pass the current exact
source/history screen. An affine-surface diagnostic raises the reconstruction
count to 2496, but is not an evolution method or a qualified mask. Next work
requires positivity-preserving surface-gradient transfers, topology/connectivity
vetoes, source-availability controls, shared subface/donor consistency and
leaf-native execution with persistent fine soil/history. Fine transfer costs of
roughly 72–80 µs/step and unchanged fine CFL/source costs of 108–124 µs/step are
separately profiled on the larger controls.

## 8. Remaining limits

Public visibility and anonymous verification remain owner-controlled steps.
Independent institutional/legal review is not recorded. Stable benchmarking is
numerical context, not calibration or universal hydraulic qualification. LI
retains material spatial errors in the uncalibrated example; whole-event NRMSE
does not excuse its peak or inundation differences. The new dev optimisation
has phase coverage but no new 72-hour timing. Static methods remain experimental;
no qualified Orton Bradley static/adaptive event exists. Dynamic AMR, sparse
hydraulic storage, wavelets, mixed-precision FV1 and temporal subcycling remain
unimplemented or deferred at their separate gates.
