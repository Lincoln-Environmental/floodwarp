Each manifest identifies one complete physical/numerical configuration and execution environment. The configuration ID excludes repeats of identical attempts. The execution ID includes source content, hardware and upstream attempt identifiers. A force run creates a new attempt under the same case. Logs, initial attempt metadata, output checksums and terminal receipts live at the recorded paths. Failed or interrupted attempts retain their directories. A running attempt without a terminal receipt is incomplete. The current manifests select attempts for processing. Raw data arrays can be regenerated by executing their case. Durations and distances use SI units.

The processed attempt catalogue maps archived attempts to physical forcing/grid identifiers and hydraulic configuration identifiers. Exact repeats share a hydraulic configuration identifier even when they serve as separate timing observations in different stages. Source changes distinguish implementations. The SQLite experiments table links the receipt identifier to numerical and hardware metadata. Archived incomplete or failed attempt records retain their status. Table verification compares every SQL value to its CSV and regenerates each published table in a temporary directory.
